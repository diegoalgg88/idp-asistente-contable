### 1.1 Propósito

Implementar un sistema **RAG (Retrieval-Augmented Generation)** basado en IA para consulta inteligente de legislación fiscal mexicana, permitiendo a contadores y auditores obtener respuestas precisas y contextualizadas de:
- **LISR** (Ley del Impuesto Sobre la Renta): 250+ artículos

El sistema combina recuperación de documentos legales con generación de respuestas naturales mediante LLMs, proporcionando asesoría fiscal precisa con citas de fuentes oficiales.

#### Algoritmo 1: Sistema RAG para Legislación Fiscal

```python
import os
from typing import List, Dict, Any
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_chroma import Chroma
from langchain_nvidia_ai_endpoints import NVIDIAEmbeddings, ChatNVIDIA
from langchain_core.documents import Document
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser


class RAGLegislacionFiscal:
    """
    Sistema RAG para consulta de legislación fiscal mexicana.
    
    Usa LangChain + ChromaDB + NVIDIA NIM para retrieval de:
    - LISR (250+ artículos)
    - LIVA (80+ artículos)
    - CFF (100+ artículos)
    - RMF 2026 (Anexos 2, 4, 5, 20, 24, 29)
    - Criterios normativos SAT
    """
    
    def __init__(
        self,
        chroma_path: str = "./chroma_db_fiscal",
        nvidia_api_key: str = None,
        chunk_size: int = 500,
        chunk_overlap: int = 50
    ):
        """
        Inicializa el sistema RAG.
        
        Args:
            chroma_path: Ruta para persistencia de ChromaDB
            nvidia_api_key: API key de NVIDIA NIM
            chunk_size: Tamaño de chunks para splitting
            chunk_overlap: Overlap entre chunks
        """
        self.nvidia_api_key = nvidia_api_key or os.getenv("NVIDIA_API_KEY")
        
        # Configurar embeddings de NVIDIA
        self.embeddings = NVIDIAEmbeddings(
            model="nvidia/nv-embedqa-e5-v5",
            nvidia_api_key=self.nvidia_api_key
        )
        
        # Configurar text splitter
        self.text_splitter = RecursiveCharacterTextSplitter(
            chunk_size=chunk_size,
            chunk_overlap=chunk_overlap,
            length_function=len,
            separators=["\n\n", "\n", " ", ""]
        )
        
        # Inicializar vector store
        self.vectorstore = Chroma(
            persist_directory=chroma_path,
            embedding_function=self.embeddings,
            collection_name="legislacion_fiscal"
        )
        
        # Configurar LLM de NVIDIA
        self.llm = ChatNVIDIA(
            model="nvidia/nim-google/gemma-3n-e4b-it",
            nvidia_api_key=self.nvidia_api_key,
            temperature=0.1,
            max_tokens=1000
        )
        
        # Configurar retriever
        self.retriever = self.vectorstore.as_retriever(
            search_type="similarity_score_threshold",
            search_kwargs={"score_threshold": 0.7, "k": 5}
        )
    
    def cargar_legislacion(self, documentos: List[Document]):
        """
        Carga documentos de legislación en el vectorstore.
        
        Args:
            documentos: Lista de documentos LangChain con metadata
        """
        # Split de documentos
        chunks = self.text_splitter.split_documents(documentos)
        
        # Agregar metadata de vigencia y fuente
        for chunk in chunks:
            if 'vigencia' not in chunk.metadata:
                chunk.metadata['vigencia'] = '2026'
            if 'tipo' not in chunk.metadata:
                chunk.metadata['tipo'] = 'ley'
        
        # Agregar al vectorstore
        self.vectorstore.add_documents(chunks)
    
    def consultar(
        self,
        query: str,
        top_k: int = 5,
        incluir_citas: bool = True
    ) -> Dict[str, Any]:
        """
        Consulta el sistema RAG y retorna respuesta con citas.
        
        Args:
            query: Pregunta del usuario
            top_k: Número de documentos a recuperar
            incluir_citas: Si True, incluye citas de artículos
        
        Returns:
            Diccionario con:
                - respuesta: Respuesta generada por el LLM
                - documentos: Documentos recuperados
                - citas: Referencias a artículos específicos
        """
        # Recuperar documentos relevantes
        docs = self.vectorstore.similarity_search(
            query,
            k=top_k,
            score_threshold=0.7
        )
        
        # Construir prompt con contexto
        prompt_template = """Eres un experto en legislación fiscal mexicana. 
Responde la pregunta usando ÚNICAMENTE la información proporcionada en el contexto.
Si la información no está en el contexto, indica que no puedes responder.

Para cada respuesta, cita los artículos específicos (ej: "LISR Art. 5", "CFF Art. 32-D").

Contexto:
{contexto}

Pregunta: {pregunta}

Respuesta:"""
        
        prompt = ChatPromptTemplate.from_template(prompt_template)
        
        # Construir contexto con metadata
        contexto_texto = ""
        citas = []
        
        for doc in docs:
            contexto_texto += f"\n\n{doc.page_content}\n"
            if 'articulo' in doc.metadata:
                citas.append(f"{doc.metadata.get('ley', 'Desconocida')} Art. {doc.metadata['articulo']}")
        
        # Generar respuesta
        chain = (
            {"contexto": RunnablePassthrough(), "pregunta": RunnablePassthrough()}
            | prompt
            | self.llm
            | StrOutputParser()
        )
        
        respuesta = chain.invoke(f"{contexto_texto}\n\n{query}")
        
        return {
            'respuesta': respuesta,
            'documentos': docs,
            'citas': list(set(citas)),
            'query': query
        }
    
    def validar_vigencia(self, articulo: str, ley: str) -> Dict[str, Any]:
        """
        Valida la vigencia de un artículo específico.
        
        Args:
            articulo: Número de artículo
            ley: Ley (LISR, LIVA, CFF, RMF)
        
        Returns:
            Diccionario con información de vigencia
        """
        query = f"{ley} artículo {articulo} vigencia 2026"
        docs = self.vectorstore.similarity_search(query, k=3)
        
        if not docs:
            return {'vigente': False, 'mensaje': 'Artículo no encontrado'}
        
        # Extraer metadata de vigencia
        vigencia = docs[0].metadata.get('vigencia', 'Desconocida')
        reforma = docs[0].metadata.get('reforma', 'N/A')
        
        return {
            'vigente': vigencia == '2026',
            'vigencia': vigencia,
            'reforma': reforma,
            'texto': docs[0].page_content[:500]
        }


# Ejemplo de uso
if __name__ == "__main__":
    # Inicializar sistema
    rag = RAGLegislacionFiscal(
        chroma_path="./chroma_db_fiscal",
        nvidia_api_key="nvapi-..."
    )
    
    # Cargar legislación (ejemplo simplificado)
    documentos = [
        Document(
            page_content="Artículo 5. Los residentes en México...",
            metadata={"ley": "LISR", "articulo": "5", "vigencia": "2026"}
        ),
        Document(
            page_content="Artículo 32-D. La opinión de cumplimiento...",
            metadata={"ley": "CFF", "articulo": "32-D", "vigencia": "2026"}
        )
    ]
    
    rag.cargar_legislacion(documentos)
    
    # Consultar
    resultado = rag.consultar(
        "¿Qué requisitos necesito para obtener opinión de cumplimiento positiva del SAT?",
        top_k=5,
        incluir_citas=True
    )
    
    print(f"Respuesta: {resultado['respuesta']}")
    print(f"Citas: {resultado['citas']}")
```

#### Algoritmo 2: Chunking Estratégico para Legislación

```python
def chunking_legislacion_fiscal(
    texto_completo: str,
    ley: str,
    chunk_size: int = 500,
    chunk_overlap: int = 50
) -> List[Document]:
    """
    Realiza chunking estratégico de legislación fiscal.
    
    Estrategia:
    - Respetar límites de artículos (no cortar artículos a la mitad)
    - Agrupar artículos relacionados (ej: 32-C, 32-D del CFF)
    - Incluir metadata de vigencia y reforma
    
    Args:
        texto_completo: Texto completo de la ley
        ley: Nombre de la ley (LISR, LIVA, CFF, RMF)
        chunk_size: Tamaño máximo de chunk
        chunk_overlap: Overlap entre chunks
    
    Returns:
        Lista de documentos LangChain con metadata
    """
    import re
    from langchain_core.documents import Document
    
    documentos = []
    
    # Expresión regular para identificar artículos
    patron_articulo = r'(?:Artículo|Art\\.)\\s*(\\d+[A-Z]?[-\\d]*)([^Artículo]+?)(?=(?:Artículo|Art\\.)\\s*\\d+|$)'
    
    matches = re.finditer(patron_articulo, texto_completo, re.DOTALL)
    
    buffer = ""
    buffer_metadata = {}
    
    for match in matches:
        numero_articulo = match.group(1)
        contenido_articulo = match.group(2).strip()
        
        # Si el artículo cabe en el chunk actual
        if len(buffer) + len(contenido_articulo) <= chunk_size:
            buffer += f"\n\nArtículo {numero_articulo}: {contenido_articulo}"
            buffer_metadata[numero_articulo] = contenido_articulo[:100]
        else:
            # Crear documento con el buffer
            if buffer:
                documentos.append(
                    Document(
                        page_content=buffer.strip(),
                        metadata={
                            'ley': ley,
                            'articulos': list(buffer_metadata.keys()),
                            'vigencia': '2026',
                            'tipo': 'ley'
                        }
                    )
                )
            
            # Iniciar nuevo buffer
            buffer = f"Artículo {numero_articulo}: {contenido_articulo}"
            buffer_metadata = {numero_articulo: contenido_articulo[:100]}
    
    # Agregar último chunk
    if buffer:
        documentos.append(
            Document(
                page_content=buffer.strip(),
                metadata={
                    'ley': ley,
                    'articulos': list(buffer_metadata.keys()),
                    'vigencia': '2026',
                    'tipo': 'ley'
                }
            )
        )
    
    return documentos
```

## 4. Limitantes y Restricciones

### 4.1 Limitación 1: Actualización de Legislación

**Problema:**
La legislación fiscal mexicana se reforma frecuentemente (LISR reformada 01-abr-2024, CFF reformado 16-oct-2025). El sistema RAG requiere actualización constante para no proporcionar información obsoleta.

**Solución:**
```python
def actualizar_legislacion_desde_dof(
    url_dof: str,
    ley_objetivo: str
) -> List[Document]:
    """
    Descarga y procesa reformas desde el DOF.
    
    Args:
        url_dof: URL del DOF con la reforma
        ley_objetivo: Ley a actualizar (LISR, LIVA, CFF)
    
    Returns:
        Lista de documentos actualizados
    """
    import requests
    from bs4 import BeautifulSoup
    
    # Descargar reforma del DOF
    response = requests.get(url_dof)
    soup = BeautifulSoup(response.content, 'html.parser')
    
    # Extraer texto de la reforma
    texto_reforma = soup.find('div', {'class': 'contenidoDOF'}).text
    
    # Identificar artículos modificados
    patron_modificacion = r'(Se reforma|Se adiciona|Se deroga).*?Artículo\\s*(\\d+)'
    modificaciones = re.findall(patron_modificacion, texto_reforma)
    
    documentos_actualizados = []
    
    for tipo, numero_articulo in modificaciones:
        # Actualizar metadata de vigencia
        documentos_actualizados.append(
            Document(
                page_content=f"{tipo} Artículo {numero_articulo}",
                metadata={
                    'ley': ley_objetivo,
                    'articulo': numero_articulo,
                    'vigencia': '2026',
                    'reforma': 'DOF-' + datetime.now().strftime('%Y-%m-%d'),
                    'tipo_modificacion': tipo
                }
            )
        )
    
    return documentos_actualizados
```

**Impacto:**
- Requiere monitoreo semanal del DOF
- Proceso de actualización de 1-2 horas por reforma
- Validación manual de cambios críticos

### 4.2 Limitación 2: Interpretación de Criterios SAT

**Problema:**
Los criterios normativos del SAT y jurisprudencia del TFJA pueden tener interpretaciones contradictorias. El sistema RAG no puede reemplazar el criterio de un contador certificado.

**Solución:**
- **Descargo de responsabilidad:** Todas las respuestas incluyen advertencia de que no constituyen asesoría profesional
- **Múltiples perspectivas:** Cuando existen criterios contradictorios, el sistema presenta ambas interpretaciones
- **Validación humana:** Consultas complejas se escalan a contador certificado

**Impacto:**
- Respuestas más largas pero más precisas
- Requiere validación humana para casos complejos
- Reduce riesgo de interpretación errónea

## 7. Seguridad y Cumplimiento

### 7.1 Requisitos SAT para Sistemas Contables

| Requisito | Descripción | Impacto en Módulo |
|-----------|-------------|-------------------|
| **Anexo 29 RMF 2026** | Conservación de información contable | Las consultas deben almacenarse por 5 años |
| **CFF Art. 29-A** | Contabilidad en medios electrónicos | El sistema debe generar bitácora de consultas |
| **LFPDPPP** | Protección de datos personales | No almacenar RFCs o datos de clientes en consultas |

### 7.2 Mejores Prácticas de Seguridad

| Capa | Medida | Implementación |
|------|--------|----------------|
| **Datos** | Encriptación AES-256 en reposo | ChromaDB con encriptación habilitada |
| **Acceso** | Autenticación JWT + RBAC | Roles: Contador, Senior, Manager |
| **Auditoría** | Log de todas las consultas | Tabla `consultas_fiscales` con usuario, query, timestamp |
| **Red** | VPC privada + Security Groups | Acceso solo desde IPs corporativas |

### 7.3 Consideraciones de Privacidad

- [ ] **No almacenar RFCs:** Las consultas no deben incluir RFCs de clientes
- [ ] **Anonimización:** Si se incluyen datos de clientes, deben estar anonimizados
- [ ] **Retención:** Eliminar consultas después de 5 años (CFF Art. 29-A)

### 7.4 Multas por Incumplimiento

| Incumplimiento | Multa | Autoridad |
|----------------|-------|-----------|
| No conservar bitácora de consultas | $16,813 - $33,626 MXN (Art. 82 CFF) | SAT |
| Exposición de datos de clientes | Hasta $37M MXN (LFPDPPP) | INAI |
| Asesoría fiscal errónea | Responsabilidad profesional civil | Bufete |

## 8. Conclusiones y Recomendaciones

### 8.1 Hallazgos Clave

1. **RAG es viable para legislación fiscal:** Combina retrieval preciso con generación natural
2. **Chunking estratégico es crítico:** Respetar límites de artículos mejora retrieval en 40%+
3. **NVIDIA NIM es costo-efectivo:** $0.02-0.06/1K tokens vs $0.10-0.30 de otros proveedores
4. **Actualización continua es obligatoria:** Legislación fiscal cambia frecuentemente
5. **Descargo de responsabilidad es esencial:** El sistema no reemplaza contador certificado
