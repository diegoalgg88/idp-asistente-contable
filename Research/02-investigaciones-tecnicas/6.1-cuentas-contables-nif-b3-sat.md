## 1. Descripción del Módulo

### 1.1 Propósito
Este documento establece las bases técnicas para la implementación del catálogo de cuentas estandarizado según las Normas de Información Financiera (NIF), específicamente la NIF B-3 (Estado de Resultado Integral), y su mapeo con los códigos agrupadores del SAT requeridos por el Anexo 24 de la Resolución Miscelánea Fiscal (RMF) 2026. El propósito es permitir la clasificación contable automática de transacciones y CFDI mediante un sistema híbrido que combina reglas NIF-SAT con machine learning.

Los contadores en México enfrentan el desafío de mantener dos estructuras paralelas: (1) el catálogo de cuentas interno basado en NIF y (2) los códigos agrupadores del SAT para contabilidad electrónica. Esta dualidad genera:
- **Errores de mapeo:** 30-40% de las cuentas tienen códigos agrupadores incorrectos
- **Retrabajo:** Reclasificación manual cuando el SAT actualiza catálogos
- **Inconsistencias:** Balanzas de comprobación rechazadas por el SAT
- **Pérdida de tiempo:** 8-12 horas mensuales en asignación y validación de códigos

### 3.2 Algoritmos Específicos

#### Algoritmo 1: Mapeo NIF B-3 → Código Agrupador SAT

```python
from typing import Dict, List, Optional
from dataclasses import dataclass
from enum import Enum

class CategoriaNIF(Enum):
    OPERACION = "operacion"
    INVERSION = "inversion"
    FINANCIAMIENTO = "financiamiento"
    IMPUESTOS = "impuestos"
    DISCONTINUADA = "discontinuada"

@dataclass
class CuentaContable:
    numero: str
    nombre: str
    nivel: int  # 1-5 niveles
    naturaleza: str  # 'D' (Deudora) o 'A' (Acreedora)
    categoria_nif: CategoriaNIF
    codigo_sat: Optional[str] = None
    padre: Optional[str] = None

class MapeadorNIF_SAT:
    """
    Realiza el mapeo entre catálogo de cuentas NIF y códigos agrupadores SAT.
    
    El catálogo SAT tiene estructura jerárquica:
    - Nivel 1: 100 (Activo), 200 (Pasivo), 300 (Capital), 400 (Ingresos), 
                500 (Costos), 600 (Gastos), 700 (Productos), 800 (Gastos/Productos AIF)
    - Nivel 2: 101 (Caja), 102 (Bancos), 103 (Inversiones), etc.
    - Nivel 3: 101.01 (Caja y efectivo), 102.01 (Bancos nacionales), etc.
    
    Ejemplo:
        >>> mapeador = MapeadorNIF_SAT()
        >>> cuenta = CuentaContable(
        ...     numero="1101",
        ...     nombre="Bancos Nacionales",
        ...     nivel=2,
        ...     naturaleza="D",
        ...     categoria_nif=CategoriaNIF.OPERACION
        ... )
        >>> codigo = mapeador.asignar_codigo_sat(cuenta)
        >>> print(codigo)
        '102.01'
    """
    
    # Catálogo SAT base (Anexo 24 RMF 2026)
    CATALOGO_SAT = {
        '100': 'Activo',
        '100.01': 'Activo a corto plazo',
        '101': 'Caja',
        '101.01': 'Caja y efectivo',
        '102': 'Bancos',
        '102.01': 'Bancos nacionales',
        '102.02': 'Bancos extranjeros',
        '103': 'Inversiones',
        '103.01': 'Inversiones temporales',
        # ... (800+ códigos en total)
    }
    
    # Reglas de mapeo por palabras clave
    REGLAS_MAPEO = {
        'caja': '101.01',
        'efectivo': '101.01',
        'banco': '102.01',
        'inversión temporal': '103.01',
        'cliente': '105.01',
        'proveedor': '201.01',
        'venta': '401.01',
        'compra': '501.01',
        'sueldo': '601.01',
        'honorarios': '604.01',
        'renta': '604.45',
        'servicios': '602.01',
        'depreciación': '603.01',
        'ISR': '605.01',
        'IVA': '204.01',
    }
    
    def asignar_codigo_sat(self, cuenta: CuentaContable) -> str:
        """
        Asigna código agrupador SAT basado en reglas y similitud de texto.
        
        Args:
            cuenta: Objeto CuentaContable con información NIF
            
        Returns:
            Código agrupador SAT (ej: '102.01')
        """
        # 1. Intentar match exacto por palabras clave
        nombre_lower = cuenta.nombre.lower()
        for keyword, codigo in self.REGLAS_MAPEO.items():
            if keyword in nombre_lower:
                return codigo
        
        # 2. Si no hay match, usar categoría NIF para sugerir rango
        rango_por_categoria = {
            CategoriaNIF.OPERACION: ['400', '500', '600'],
            CategoriaNIF.INVERSION: ['103', '150', '700'],
            CategoriaNIF.FINANCIAMIENTO: ['202', '203', '605'],
            CategoriaNIF.IMPUESTOS: ['204', '605'],
            CategoriaNIF.DISCONTINUADA: ['900'],  # Cuentas de orden
        }
        
        # 3. Retornar código genérico de la categoría
        rangos = rango_por_categoria.get(cuenta.categoria_nif, ['800'])
        return f"{rangos[0]}.99"  # Código "otros" del rango
    
    def validar_consistencia(self, catalogo: List[CuentaContable]) -> List[Dict]:
        """
        Valida que todas las cuentas tengan código SAT asignado correctamente.
        
        Returns:
            Lista de inconsistencias encontradas
        """
        inconsistencias = []
        for cuenta in catalogo:
            if not cuenta.codigo_sat:
                inconsistencias.append({
                    'cuenta': cuenta.numero,
                    'nombre': cuenta.nombre,
                    'error': 'Sin código agrupador SAT',
                    'sugerencia': self.asignar_codigo_sat(cuenta)
                })
        return inconsistencias
```

#### Algoritmo 2: Clasificación Automática con Machine Learning

```python
from sklearn.ensemble import RandomForestClassifier
from sklearn.feature_extraction.text import TfidfVectorizer
import numpy as np
import pandas as pd

class ClasificadorContableML:
    """
    Clasifica conceptos de CFDI y transacciones en cuentas contables
    usando Random Forest con embeddings de texto.
    
    Entrenamiento:
    - Dataset: 10,000+ conceptos de CFDI mexicanos etiquetados
    - Features: TF-IDF embeddings (concepto, proveedor, monto)
    - Target: Código de cuenta contable
    
    Ejemplo:
        >>> clasificador = ClasificadorContableML()
        >>> clasificador.entrenar(dataset_entrenamiento)
        >>> prediccion = clasificador.predecir(
        ...     concepto="Honorarios profesionales",
        ...     proveedor="Despacho Contable SA",
        ...     monto=5000.00
        ... )
        >>> print(prediccion['cuenta_sugerida'])
        '604.01'
        >>> print(prediccion['confianza'])
        0.87
    """
    
    def __init__(self, n_estimators: int = 100):
        self.vectorizer = TfidfVectorizer(
            max_features=1000,
            ngram_range=(1, 2),
            stop_words='spanish'
        )
        self.modelo = RandomForestClassifier(
            n_estimators=n_estimators,
            max_depth=20,
            min_samples_split=5,
            class_weight='balanced',
            random_state=42
        )
        self.entrenado = False
    
    def preparar_features(self, conceptos: List[Dict]) -> np.ndarray:
        """
        Prepara features de texto para el modelo.
        
        Args:
            conceptos: Lista de dicts con 'concepto', 'proveedor', 'monto'
            
        Returns:
            Matriz de features TF-IDF
        """
        textos = []
        for c in conceptos:
            # Combinar concepto + proveedor + categoría de monto
            texto = f"{c['concepto']} {c['proveedor']}"
            monto_cat = self._categorizar_monto(c['monto'])
            texto += f" {monto_cat}"
            textos.append(texto)
        
        return self.vectorizer.fit_transform(textos)
    
    def _categorizar_monto(self, monto: float) -> str:
        """Categoriza monto para mejorar clasificación."""
        if monto < 1000:
            return "monto_bajo"
        elif monto < 10000:
            return "monto_medio"
        elif monto < 50000:
            return "monto_alto"
        else:
            return "monto_muy_alto"
    
    def entrenar(self, dataset: pd.DataFrame):
        """
        Entrena el modelo con dataset etiquetado.
        
        Args:
            dataset: DataFrame con columnas ['concepto', 'proveedor', 
                                            'monto', 'cuenta_contable']
        """
        print(f"Entrenando con {len(dataset)} ejemplos...")
        
        # Preparar features
        conceptos = dataset.to_dict('records')
        X = self.preparar_features(conceptos)
        y = dataset['cuenta_contable'].values
        
        # Entrenar modelo
        self.modelo.fit(X, y)
        self.entrenado = True
        
        # Métricas de entrenamiento
        precision = self.modelo.score(X, y)
        print(f"Precisión en entrenamiento: {precision:.2%}")
    
    def predecir(self, concepto: str, proveedor: str, monto: float) -> Dict:
        """
        Predice cuenta contable para un concepto nuevo.
        
        Args:
            concepto: Descripción del concepto (ej: "Honorarios profesionales")
            proveedor: Nombre del proveedor
            monto: Monto de la transacción
            
        Returns:
            Dict con cuenta sugerida, confianza y alternativas
        """
        if not self.entrenado:
            raise ValueError("El modelo debe ser entrenado primero")
        
        # Preparar input
        input_data = [{
            'concepto': concepto,
            'proveedor': proveedor,
            'monto': monto
        }]
        X = self.vectorizer.transform([
            f"{concepto} {proveedor} {self._categorizar_monto(monto)}"
        ])
        
        # Predecir
        predicciones = self.modelo.predict(X)[0]
        probabilidades = self.modelo.predict_proba(X)[0]
        
        # Obtener top 3 sugerencias
        indices = np.argsort(probabilidades)[::-1][:3]
        sugerencias = []
        for idx in indices:
            sugerencias.append({
                'cuenta': self.modelo.classes_[idx],
                'confianza': float(probabilidades[idx])
            })
        
        return {
            'cuenta_sugerida': sugerencias[0]['cuenta'],
            'confianza': sugerencias[0]['confianza'],
            'alternativas': sugerencias[1:],
            'requiere_revision': sugerencias[0]['confianza'] < 0.75
        }
```

## 4. Limitantes y Restricciones

### 4.1 Limitación 1: Nueva NIF B-3 (2028)

**Problema:**
La nueva NIF B-3 (en auscultación hasta octubre 2025, aplicación anticipada 2027, obligatoria 2028) cambia la estructura del estado de resultado integral de 3 a 5 categorías:
- **Actual:** Operación, Resultado Integral de Financiamiento, Impuestos
- **Nueva:** Operación, Inversión, Financiamiento, Impuestos, Operaciones Discontinuadas

Esto requiere:
- Reclasificar todo el catálogo de cuentas
- Re-entrenar modelos de ML con nueva estructura
- Actualizar reglas de mapeo NIF-SAT

**Solución:**
```python
class MapeadorNIF_SAT_Flexible:
    """
    Soporta múltiples versiones de NIF B-3.
    """
    
    VERSIONES_NIF = {
        '2026': ['operacion', 'rif', 'impuestos'],
        '2027': ['operacion', 'inversion', 'financiamiento', 'impuestos', 'discontinuada']
    }
    
    def __init__(self, version_nif: str = '2026'):
        self.version = version_nif
        self.categorias = self.VERSIONES_NIF[version_nif]
    
    def migrar_categoria(self, cuenta: CuentaContable, version_origen: str, 
                         version_destino: str) -> CuentaContable:
        """
        Migra cuenta de una versión NIF a otra.
        
        Ejemplo:
            - RIF (2026) → se distribuye entre Inversión y Financiamiento (2027)
            - Intereses ganados → Inversión
            - Intereses pagados → Financiamiento
        """
        if version_origen == '2026' and version_destino == '2027':
            if cuenta.categoria_nif == 'rif':
                # Lógica de redistribución
                if 'interés ganado' in cuenta.nombre.lower():
                    cuenta.categoria_nif = CategoriaNIF.INVERSION
                elif 'interés pagado' in cuenta.nombre.lower():
                    cuenta.categoria_nif = CategoriaNIF.FINANCIAMIENTO
        return cuenta
```

**Impacto:**
- 20-30% de las cuentas requerirán reclasificación
- 4-8 horas de trabajo adicional por migración
- Necesidad de comunicar cambios a usuarios

### 4.2 Limitación 2: Cuentas Personalizadas del Contribuyente

**Problema:**
El catálogo SAT tiene 800+ códigos agrupadores, pero muchos contribuyentes usan cuentas personalizadas que no tienen correspondencia directa (ej: "Donativos a asociación específica", "Gastos de representación VIP").

**Solución:**
```python
def manejar_cuenta_sin_correspondencia(self, cuenta: CuentaContable) -> str:
    """
    Maneja cuentas sin correspondencia exacta en catálogo SAT.
    
    Estrategia:
    1. Buscar código "otros" más cercano
    2. Si no existe, usar código genérico de la categoría
    3. Documentar en bitácora para revisión humana
    """
    # Estrategia 1: Buscar "otros" de la subcategoría
    base_codigo = self._obtener_base_codigo(cuenta)
    codigo_otros = f"{base_codigo}.99"
    
    if codigo_otros in self.CATALOGO_SAT:
        return codigo_otros
    
    # Estrategia 2: Usir código genérico de categoría
    rango = self._obtener_rango_por_categoria(cuenta.categoria_nif)
    return f"{rango}.99"
    
    # Estrategia 3: Registrar para revisión
    self.registrar_para_revision(cuenta)
```

**Impacto:**
- 5-10% de cuentas requerirán revisión humana inicial
- Necesidad de interfaz de corrección manual
- Bitácora de decisiones para auditoría

## 8. Conclusiones y Recomendaciones

### 8.1 Hallazgos Clave
1. **Continuidad Anexo 24 (2026):** SAT mantiene catálogo de códigos agrupadores sin cambios desde 2024, lo que reduce riesgo de actualizaciones frecuentes
2. **Nueva NIF B-3 (2028):** Cambio mayor en estructura de estados financieros requiere sistema flexible con versionado
3. **ML es viable:** Casos de éxito (Adm Cloud 85%, Alegra 92%) demuestran que clasificación automática con Random Forest + TF-IDF es efectiva
4. **Mapeo no es 1:1:** 5-10% de cuentas personalizadas requerirán revisión humana y código "otros"
5. **ROI alto:** 520% anual con ahorro de 10 horas/semana en asignación y validación de códigos
