## 1. Descripción del Módulo

### 1.1 Propósito

Definir la metodología y checklist de Due Diligence Financiero para procesos de fusiones y adquisiciones (M&A) en México, permitiendo a auditores externos y compradores evaluar la salud financiera real de empresas objetivo, identificar riesgos ocultos, validar calidad de utilidades (Quality of Earnings), y fundamentar decisiones de valoración y estructuración de acuerdos.

El Due Diligence Financiero es crítico para M&A porque:
- **Valida información financiera:** Confirma que estados financieros reflejan realidad económica del negocio
- **Identifica riesgos ocultos:** Detecta pasivos contingentes, litigios, irregularidades fiscales no evidentes
- **Ajusta valoración:** EBITDA ajustado revela capacidad real de generación de caja
- **Fundamenta negociación:** Hallazgos cuantificados permiten ajustar precio o incluir cláusulas de protección
- **Previene sorpresas post-cierre:** 70% de adquisiciones fallan por due diligence incompleto

### 1.2 Actividades del Auditor que Automatiza

### 1.3 Dolor Principal que Resuelve

**Problema central:** Los auditores y compradores en procesos M&A enfrentan:

1. **Información financiera incompleta:** Estados financieros sin desglose, notas incompletas, inconsistencias entre ejercicios
2. **EBITDA inflado:** Empresas objetivo presentan EBITDA con ajustes agresivos que no reflejan operación real
3. **Pasivos ocultos:** Deudas no registradas, litigios contingentes, obligaciones fiscales no provisionadas
4. **Falta de estandarización:** Cada firma de due diligence usa metodologías diferentes, dificultando comparación
5. **Tiempo excesivo:** Procesos de 6-12 semanas que retrasan cierres y aumentan costos de transacción
6. **Riesgo de sobrevaloración:** 40% de adquisiciones pagan más del valor real por due diligence deficiente

**Impacto emocional:** Estrés por riesgo de cerrar mal negocio, presión de inversionistas, miedo a responsabilidades post-cierre.

### 3.3 Cálculo de EBITDA Ajustado

```python
from decimal import Decimal, ROUND_HALF_UP

class EBITDACalculator:
    """
    Calcula EBITDA ajustado para due diligence financiero.
    
    Fórmula:
    EBITDA = Utilidad Operativa + Depreciación + Amortización
    EBITDA Ajustado = EBITDA + Ajustes No Recurrentes + Ajustes de Relacionados
    """
    
    def __init__(self, utilidad_operativa: Decimal, depreciacion: Decimal, amortizacion: Decimal):
        self.utilidad_operativa = utilidad_operativa
        self.depreciacion = depreciacion
        self.amortizacion = amortizacion
        self.ajustes = []
    
    def calcular_ebitda_base(self) -> Decimal:
        """
        Calcula EBITDA base sin ajustes.
        """
        ebitda = self.utilidad_operativa + self.depreciacion + self.amortizacion
        return ebitda.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
    
    def agregar_ajuste_no_recurrente(self, concepto: str, monto: Decimal, es_ingreso: bool = False):
        """
        Agrega ajuste por concepto no recurrente.
        
        Ejemplos:
        - Ganancia/pérdida por venta de activos
        - Costos de reestructuración
        - Litigios extraordinarios
        - Efectos de cambios fiscales
        """
        self.ajustes.append({
            'tipo': 'no_recurrente',
            'concepto': concepto,
            'monto': monto,
            'es_ingreso': es_ingreso  # True si es ingreso, False si es gasto
        })
    
    def agregar_ajuste_relacionados(self, concepto: str, monto_mercado: Decimal, monto_registrado: Decimal):
        """
        Agrega ajuste por operaciones con relacionados.
        
        Ejemplos:
        - Sueldos de socios por encima de mercado
        - Rentas de inmuebles de relacionados
        - Intereses de deuda con relacionados
        """
        diferencia = monto_mercado - monto_registrado
        self.ajustes.append({
            'tipo': 'relacionados',
            'concepto': concepto,
            'monto_mercado': monto_mercado,
            'monto_registrado': monto_registrado,
            'ajuste': diferencia
        })
    
    def calcular_ebitda_ajustado(self) -> Decimal:
        """
        Calcula EBITDA ajustado sumando/restando ajustes.
        """
        ebitda_base = self.calcular_ebitda_base()
        
        # Aplicar ajustes
        total_ajustes = Decimal('0')
        for ajuste in self.ajustes:
            if ajuste['tipo'] == 'no_recurrente':
                # Si es gasto no recurrente, se suma de vuelta (reduce utilidad)
                # Si es ingreso no recurrente, se resta (aumentó utilidad)
                if ajuste['es_ingreso']:
                    total_ajustes -= ajuste['monto']
                else:
                    total_ajustes += ajuste['monto']
            elif ajuste['tipo'] == 'relacionados':
                # Ajusta a valor de mercado
                total_ajustes += ajuste['ajuste']
        
        ebitda_ajustado = ebitda_base + total_ajustes
        return ebitda_ajustado.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
    
    def generar_reporte(self) -> dict:
        """
        Genera reporte detallado de EBITDA ajustado.
        """
        return {
            'utilidad_operativa': str(self.utilidad_operativa),
            'depreciacion': str(self.depreciacion),
            'amortizacion': str(self.amortizacion),
            'ebitda_base': str(self.calcular_ebitda_base()),
            'ajustes_desglosados': self.ajustes,
            'total_ajustes': str(sum(
                a['monto'] if a['tipo'] == 'no_recurrente' and not a['es_ingreso']
                else -a['monto'] if a['tipo'] == 'no_recurrente' and a['es_ingreso']
                else a['ajuste']
                for a in self.ajustes
            )),
            'ebitda_ajustado': str(self.calcular_ebitda_ajustado()),
        }


# Ejemplo de uso
if __name__ == '__main__':
    # Datos del ejercicio 2025
    calculator = EBITDACalculator(
        utilidad_operativa=Decimal('5000000'),
```

### 3.4 Validación de Proveedores con SAT

```python
import requests
from datetime import datetime

class SATValidator:
    """
    Valida proveedores contra SAT (lista 69-B, opinión cumplimiento, CFDI).
    """
    
    def __init__(self, rfc_emisor: str, csd_cert: str, csd_key: str, password: str):
        self.rfc_emisor = rfc_emisor
        self.csd_cert = csd_cert
        self.csd_key = csd_key
        self.password = password
        self.base_url = 'https://www.sat.gob.mx/aplicacion/operacion/31274'
    
    def validar_lista_69b(self, rfc_proveedor: str) -> dict:
        """
        Verifica si proveedor está en lista 69-B (EFOS/EDOS).
        """
        # Nota: En producción, usar API oficial o servicio de terceros (Gigstack)
        response = requests.get(
            f'{self.base_url}/verificar-lista-69b',
            params={'rfc': rfc_proveedor}
        )
        
        if response.status_code == 200:
            data = response.json()
            return {
                'en_lista_69b': data.get('en_lista', False),
                'tipo': data.get('tipo', None),  # 'EFOS' o 'EDOS'
                'fecha_publicacion': data.get('fecha_publicacion', None),
                'estatus': 'NO_CONFINABLE' if not data.get('en_lista') else 'CONFINABLE'
            }
        
        raise Exception(f"Error al validar lista 69-B: {response.text}")
    
    def validar_opinion_cumplimiento(self, rfc_proveedor: str) -> dict:
        """
        Obtiene opinión de cumplimiento del proveedor.
        """
        response = requests.get(
            f'{self.base_url}/opinion-cumplimiento',
            params={'rfc': rfc_proveedor}
        )
        
        if response.status_code == 200:
            data = response.json()
            return {
                'estatus': data.get('estatus', 'DESCONOCIDO'),  # 'POSITIVO' o 'NEGATIVO'
                'vigencia': data.get('vigencia', None),
                'creditos_fiscales': data.get('creditos_fiscales', 0),
            }
        
        raise Exception(f"Error al validar opinión: {response.text}")
    
    def validar_cfdi_proveedor(self, rfc_proveedor: str, total_compras_anual: Decimal) -> dict:
        """
        Valida CFDI recibidos del proveedor vs. contabilidad.
        """
        # Cruce de información: CFDI timbrados vs. registros contables
        return {
            'cfdi_timbrados': 150,  # Ejemplo
            'cfdi_registrados': 148,
            'diferencia': 2,
            'monto_timbrado': Decimal('1200000'),
            'monto_registrado': Decimal('1180000'),
            'discrepancia_monto': Decimal('20000'),
            'riesgo': 'BAJO' if abs(Decimal('20000')) < Decimal('50000') else 'ALTO'
        }

def validar_proveedores_criticos(proveedores: list):
    """
    Valida proveedores que representan >5% de compras totales.
    """
    sat_validator = SATValidator(
        rfc_emisor='EMP123456789',
        csd_cert='ruta_cert.cer',
        csd_key='ruta_key.key',
        password='password'
    )
    
    resultados = []
    for proveedor in proveedores:
        rfc = proveedor['rfc']
        nombre = proveedor['nombre']
        compras_anual = proveedor['compras_anual']
        
        # Validar lista 69-B
        lista_69b = sat_validator.validar_lista_69b(rfc)
        
        # Validar opinión cumplimiento
        opinion = sat_validator.validar_opinion_cumplimiento(rfc)
        
        # Validar CFDI
        cfdi = sat_validator.validar_cfdi_proveedor(rfc, compras_anual)
        
        # Determinar riesgo
        riesgo = 'BAJO'
        if lista_69b['en_lista_69b']:
            riesgo = 'CRITICO'
        elif opinion['estatus'] == 'NEGATIVO':
            riesgo = 'ALTO'
        elif cfdi['riesgo'] == 'ALTO':
            riesgo = 'MEDIO'
        
        resultados.append({
            'rfc': rfc,
            'nombre': nombre,
            'compras_anual': str(compras_anual),
            'lista_69b': lista_69b,
            'opinion_cumplimiento': opinion,
            'cfdi_cruce': cfdi,
            'riesgo': riesgo,
        })
    
    return resultados
```

## 4. Limitantes y Restricciones

### 4.1 Limitación 1: Acceso a Información Incompleta

**Problema:**
Empresas objetivo no tienen estados financieros auditados, registros contables incompletos, o se niegan a proporcionar información sensible antes de firmar LOI (Letter of Intent).

**Solución:**
```python
# Due Diligence por fases (pre-LOI vs. post-LOI)
DUE_DILIGENCE_FASES = {
    'pre_loi': {
        'informacion_publica': [
            'Estados financieros básicos (no auditados)',
            'Opinión de cumplimiento SAT',
            'Información corporativa básica',
        ],
        'alcance': 'Limitado a información pública y no confidencial',
        'objetivo': 'Determinar si procede con LOI',
    },
    'post_loi': {
        'informacion_completa': [
            'Estados financieros auditados (3-5 años)',
            'Desglose de ingresos por cliente/producto',
            'Contratos clave (clientes, proveedores, deuda)',
            'Litigios y pasivos contingentes',
            'Información fiscal completa',
        ],
        'alcance': 'Acceso completo a data room virtual',
        'objetivo': 'Validar valoración y estructurar acuerdo',
    }
}
```

**Impacto:**
- Due diligence pre-LOI puede subestimar riesgos
- Requiere cláusulas de protección en LOI (access termination fee)
- Posible retraso de 2-4 semanas para obtener información completa

### 4.2 Limitación 2: Validación SAT con e.firma

**Problema:**
Validación de CFDI y opinión de cumplimiento requiere e.firma (CSD) del contribuyente, que solo puede ser obtenida por representante legal de la empresa objetivo.

**Solución:**
```python
# Alternativas de validación sin e.firma directa
VALIDACION_SAT_ALTERNATIVAS = {
    'opcion_1_terceros': {
        'proveedor': 'Gigstack, SW Sapien, Finkok',
        'requiere_efirma': False,
        'costo': '$500-2,000 MXN/mes',
        'limitaciones': 'Solo validaciones básicas (no descarga masiva)',
    },
    'opcion_2_representante': {
        'requiere': 'Representante legal proporciona e.firma temporal',
        'proceso': 'Firmar NDA + acuerdo de confidencialidad',
        'vigencia': 'e.firma válida por 4 años',
        'riesgo': 'Depende de cooperación del vendedor',
    },
    'opcion_3_contador': {
        'requiere': 'Contador de empresa objetivo colabora',
        'proceso': 'Contador ya tiene e.firma para dictamen',
        'limitaciones': 'Solo si empresa dictamina estados financieros',
    }
}
```

**Impacto:**
- Costo adicional de servicios de terceros ($6k-24k MXN/año)
- Dependencia de cooperación del vendedor
- Posible retraso de 1-2 semanas para obtener accesos

### 4.3 Riesgos Técnicos Identificados

|--------|--------------|---------|------------|-------|
| **Información financiera incompleta** | ALTA | ALTO | Fases de due diligence, cláusulas de protección | Legal |

## 8. Conclusiones y Recomendaciones

### 8.1 Hallazgos Clave

1. **Quality of Earnings es crítico:** 40% de empresas inflan EBITDA con ajustes no sustentados
2. **Validación SAT no es opcional:** Proveedores en lista 69-B = pérdida de deducción (40-50%)
3. **Data room organizado acelera proceso:** 2-3 semanas menos vs. proceso desorganizado
4. **Checklist estandarizada reduce riesgos:** 100% de áreas críticas cubiertas
5. **EBITDA ajustado bien documentado fundamenta valoración:** Diferencia de 10-30% en precio
