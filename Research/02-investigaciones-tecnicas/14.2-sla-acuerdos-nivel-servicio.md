## 1. Descripción del Módulo

### 1.1 Propósito

Definir los Acuerdos de Nivel de Servicio (SLA) óptimos para el IDP-App Asistente Contable, estableciendo métricas de disponibilidad, tiempos de respuesta, penalizaciones por incumplimiento y mecanismos de compensación que generen confianza con despachos contables y sus clientes.

El SLA es crítico para el modelo de outsourcing contable porque:
- Establece expectativas claras entre proveedor (IDP-App) y cliente (despacho contable)
- Define responsabilidades en caso de incidentes (downtime, errores de cálculo, pérdida de datos)
- Proporciona mecanismos de compensación automáticos por incumplimiento
- Genera confianza mediante transparencia en métricas de servicio
- Alinea incentivos: mejor servicio = menores penalizaciones

### 1.2 Actividades del Contador que Automatiza

| Actividad | Frecuencia | Tiempo Actual | Tiempo Esperado | Ahorro |
|-----------|------------|---------------|-----------------|--------|
| Negociación de SLA con proveedor de software | Por contrato (1-2/año) | 8-16 horas | 2 horas | 85% |
| Monitoreo de cumplimiento de SLA | Mensual | 4 horas/mes | Automático | 100% |
| Cálculo de créditos por incumplimiento | Por incidente | 2 horas | Automático | 100% |
| Reporte de métricas de servicio a clientes | Mensual | 6 horas/mes | Automático | 100% |
| Escalamiento de incidentes críticos | Por incidente | 1-2 horas | 15 minutos | 87% |

### 1.3 Dolor Principal que Resuelve

**Problema central:** Los despachos contables que contratan software SaaS enfrentan:

1. **Incertidumbre por downtime:** No saben cuánto tiempo estará disponible el sistema ni qué compensación reciben si falla
2. **Falta de transparencia:** Los proveedores no muestran métricas reales de disponibilidad y rendimiento
3. **Incidentes sin resolución:** Tickets de soporte que tardan días en resolverse sin consecuencias para el proveedor
4. **Pérdidas económicas no compensadas:** Downtime durante cierre mensual genera multas de clientes finales sin compensación
5. **Desalineación de incentivos:** El proveedor no tiene motivación económica para mejorar el servicio

**Impacto emocional:** Frustración por falta de control, desconfianza en proveedores, miedo a migrar a SaaS por riesgos operativos.

**Fórmula de cálculo:**
```python
def calcular_uptime_porcentaje(total_uptime_segundos, total_tiempo_segundos):
    """
    Calcula porcentaje de uptime.
    
    Args:
        total_uptime_segundos: Segundos que el sistema estuvo disponible
        total_tiempo_segundos: Segundos totales en el período (ej. 30 días)
    
    Returns:
        Porcentaje de uptime (0-100)
    
    Ejemplo:
        >>> calcular_uptime_porcentaje(2591940, 2592000)  # 60s downtime en 30 días
        99.9977
    """
    return (total_uptime_segundos / total_tiempo_segundos) * 100
```

### 3.3 Cálculo de Penalizaciones y Créditos

```python
from decimal import Decimal, ROUND_HALF_UP

class SLACreditCalculator:
    """
    Calcula créditos por incumplimiento de SLA.
    
    Reglas:
    - Uptime < 99.9%: 10% de crédito por cada 0.1% debajo del target
    - Response time p95 > 500ms: 5% de crédito
    - Incidente P1 sin resolver > 4h: 10% de crédito
    - Crédito máximo: 100% de factura mensual
    """
    
    def __init__(self, factura_mensual: Decimal, uptime_target: Decimal = Decimal('99.9')):
        self.factura_mensual = factura_mensual
        self.uptime_target = uptime_target
        self.creditos = []
    
    def calcular_credito_uptime(self, uptime_real: Decimal) -> Decimal:
        """
        Calcula crédito por incumplimiento de uptime.
        
        Fórmula: crédito = (uptime_target - uptime_real) × 10 × factura
        """
        if uptime_real >= self.uptime_target:
            return Decimal('0')
        
        diferencia = self.uptime_target - uptime_real
        credito = diferencia * 10 * self.factura_mensual
        
        # Redondear a 2 decimales
        credito = credito.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
        
        self.creditos.append({
            'tipo': 'uptime',
            'uptime_target': str(self.uptime_target),
            'uptime_real': str(uptime_real),
            'credito': str(credito)
        })
        
        return credito
    
    def calcular_credito_response_time(self, response_time_p95_ms: int, target_ms: int = 500) -> Decimal:
        """
        Calcula crédito por tiempo de respuesta excedido.
        """
        if response_time_p95_ms <= target_ms:
            return Decimal('0')
        
        credito = self.factura_mensual * Decimal('0.05')  # 5%
        
        self.creditos.append({
            'tipo': 'response_time',
            'target_ms': target_ms,
            'real_ms': response_time_p95_ms,
            'credito': str(credito)
        })
        
        return credito
    
    def calcular_credito_incidente_p1(self, horas_sin_resolver: int, threshold_horas: int = 4) -> Decimal:
        """
        Calcula crédito por incidente P1 sin resolver.
        """
        if horas_sin_resolver <= threshold_horas:
            return Decimal('0')
        
        credito = self.factura_mensual * Decimal('0.10')  # 10%
        
        self.creditos.append({
            'tipo': 'incidente_p1',
            'threshold_horas': threshold_horas,
            'horas_sin_resolver': horas_sin_resolver,
            'credito': str(credito)
        })
        
        return credito
    
    def calcular_credito_total(self) -> Decimal:
        """
        Calcula crédito total con tope de 100% de factura mensual.
        """
        total = sum(Decimal(c['credito']) for c in self.creditos)
        
        # Tope: 100% de factura mensual
        total = min(total, self.factura_mensual)
        
        return total.quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)
    
    def generar_reporte(self) -> dict:
        """
        Genera reporte detallado de créditos.
        """
        return {
            'factura_mensual': str(self.factura_mensual),
            'creditos_desglosados': self.creditos,
            'credito_total': str(self.calcular_credito_total()),
            'porcentaje_credito': f"{(self.calcular_credito_total() / self.factura_mensual * 100):.2f}%"
        }


# Ejemplo de uso
if __name__ == '__main__':
    # Factura mensual: $10,000 MXN
    calculator = SLACreditCalculator(factura_mensual=Decimal('10000'))
    
    # Escenario: uptime real 99.7%, response time 600ms, incidente P1 6h
    credito_uptime = calculator.calcular_credito_uptime(Decimal('99.7'))
    credito_response = calculator.calcular_credito_response_time(600)
    credito_incidente = calculator.calcular_credito_incidente_p1(6)
    
    reporte = calculator.generar_reporte()
    
    print(f"Crédito por uptime (99.7% vs 99.9%): ${credito_uptime}")
    print(f"Crédito por response time (600ms > 500ms): ${credito_response}")
    print(f"Crédito por incidente P1 (6h > 4h): ${credito_incidente}")
    print(f"Crédito total: ${reporte['credito_total']} ({reporte['porcentaje_credito']})")
    
    # Output esperado:
    # Crédito por uptime (99.7% vs 99.9%): $200.00
    # Crédito por response time (600ms > 500ms): $500.00
    # Crédito por incidente P1 (6h > 4h): $1000.00
    # Crédito total: $1700.00 (17.00%)
```

### 3.4 Implementación de Monitoreo con Uptime.com

```python
import requests
import time
from datetime import datetime, timedelta

class UptimeMonitor:
    """
    Integra con Uptime.com para monitoreo de SLA.
    """
    
    def __init__(self, api_key: str, check_id: str):
        self.api_key = api_key
        self.check_id = check_id
        self.base_url = 'https://api.uptimerobot.com/v2'
    
    def get_check_status(self) -> dict:
        """
        Obtiene estado actual del check.
        """
        response = requests.post(
            f'{self.base_url}/getMonitors',
            json={
                'api_key': self.api_key,
                'format': 'json',
                'monitors': self.check_id
            }
        )
        return response.json()
    
    def get_uptime_percentage(self, days: int = 30) -> Decimal:
        """
        Obtiene porcentaje de uptime de los últimos N días.
        """
        response = requests.post(
            f'{self.base_url}/getMonitors',
            json={
                'api_key': self.api_key,
                'format': 'json',
                'monitors': self.check_id,
                'custom_uptime_ranges': f'{days}'
            }
        )
        
        data = response.json()
        if data['stat'] == 'ok':
            uptime_str = data['monitors'][0]['custom_uptime_ranges']
            return Decimal(uptime_str.split('-')[0])
        
        raise Exception(f"Error al obtener uptime: {data}")
    
    def is_service_available(self) -> bool:
        """
        Verifica si el servicio está disponible actualmente.
        """
        status = self.get_check_status()
        if status['stat'] == 'ok':
            return status['monitors'][0]['status'] == 2  # 2 = up
        return False
```

## 4. Limitantes y Restricciones

### 4.1 Limitación 1: Downtime Planificado (Mantenimiento)

**Problema:**
El downtime planificado para mantenimiento (deployments, migraciones de DB, patches de seguridad) cuenta hacia el uptime total, penalizando al proveedor por actividades necesarias.

**Solución:**
```python
# Excluir ventanas de mantenimiento programado del cálculo de uptime
def calcular_uptime_con_mantenimiento(uptime_total, downtime_total, ventanas_mantenimiento):
    """
    Calcula uptime excluyendo ventanas de mantenimiento programado.
    
    Args:
        uptime_total: Segundos de uptime total
        downtime_total: Segundos de downtime total
        ventanas_mantenimiento: Lista de tuplas (inicio, fin) en timestamps
    
    Returns:
        Porcentaje de uptime ajustado
    """
    downtime_mantenimiento = sum(fin - inicio for inicio, fin in ventanas_mantenimiento)
    downtime_no_planificado = downtime_total - downtime_mantenimiento
    
    # Tiempo total excluyendo mantenimiento
    tiempo_total_ajustado = uptime_total + downtime_no_planificado
    
    uptime_ajustado = uptime_total / tiempo_total_ajustado * 100
    return uptime_ajustado

# Ejemplo: 30 días con 2h de mantenimiento programado
uptime_total = 2592000 - 7200  # 30 días - 2h
downtime_total = 7200  # 2h
ventanas = [(1709280000, 1709287200)]  # 2h de mantenimiento

uptime_ajustado = calcular_uptime_con_mantenimiento(uptime_total, downtime_total, ventanas)
print(f"Uptime ajustado: {uptime_ajustado:.4f}%")  # 100% (mantenimiento excluido)
```

**Impacto:**
- Requiere notificación con 48h de anticipación a clientes
- Ventanas deben ser en horarios no críticos (ej. sábado 2-4 AM)
- Máximo 4h de mantenimiento/mes excluíble

**Problema:**

**Solución:**
```python
# Cláusula de fuerza mayor en cálculo de SLA
EXCLUSIONES_FUERZA_MAYOR = [
    'desastres_naturales',  # Huracanes, terremotos, inundaciones
    'cortes_proveedor_cloud',  # AWS/Azure/GCP outage regional
    'ataques_ddos_masivos',  # >100 Gbps
    'actos_gobierno',  # Bloqueos regulatorios
    'guerra_terrorismo',  # Conflictos armados
]

def es_exclusion_fuerza_mayor(incidente: dict) -> bool:
    """
    Determina si un incidente califica como fuerza mayor.
    """
    causa_raiz = incidente.get('causa_raiz', '')
    
    for exclusion in EXCLUSIONES_FUERZA_MAYOR:
        if exclusion in causa_raiz.lower():
            return True
    
    # Verificar si AWS reporta outage en región
    if 'aws' in causa_raiz.lower() and 'outage' in causa_raiz.lower():
        aws_status = verificar_aws_health_dashboard(incidente['region'])
        if aws_status['is_aws_outage']:
            return True
    
    return False

# Ejemplo de uso
incidente = {
    'causa_raiz': 'AWS us-east-1 outage - EC2 unavailable',
    'region': 'us-east-1',
    'duracion_horas': 3
}

if es_exclusion_fuerza_mayor(incidente):
    print("✅ Incidente excluido: Fuerza mayor (AWS outage)")
else:
    print("❌ Incidente cuenta para SLA")
```

**Impacto:**
- Requiere verificación objetiva (AWS Health Dashboard, reportes oficiales)
- No aplica si proveedor no siguió mejores prácticas (multi-AZ, backups)
- Cliente debe ser notificado dentro de 2h del incidente

## 8. Conclusiones y Recomendaciones

### 8.1 Hallazgos Clave

1. **SLA de 99.9% es el estándar mínimo** para SaaS contable en México (Anexo 29)
2. **Monitoreo por tercero objetivo** (Uptime.com) genera confianza y evita disputas
3. **Créditos automáticos** sin solicitud del cliente diferencian el servicio
4. **Status page pública** es expectativa estándar en 2026 (transparencia)
5. **Tiered SLA** (Standard/Enterprise/Mission-Critical) permite segmentación por precio

### 8.2 Recomendaciones Finales
