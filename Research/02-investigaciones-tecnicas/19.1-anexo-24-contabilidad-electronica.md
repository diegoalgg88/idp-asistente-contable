## 1. Descripción del Módulo

### 1.1 Propósito

El Anexo 24 de la Resolución Miscelánea Fiscal (RMF) 2026 establece las especificaciones técnicas para llevar y enviar la contabilidad electrónica al SAT. Este documento técnico proporciona la guía completa para implementar la generación automatizada de los tres archivos XML obligatorios: Catálogo de Cuentas (CT), Balanza de Comprobación (BN/BC) y Pólizas del Periodo (PL), eliminando el proceso manual que consume 1.5-2 horas por cliente mensualmente y es propenso a errores en códigos agrupadores y estructura XML.

### 1.2 Actividades que Automatiza

| Actividad | Frecuencia | Tiempo Actual | Tiempo Esperado | Ahorro |
|-----------|------------|---------------|-----------------|--------|
| Generación catálogo de cuentas XML | Mensual | 15 min/cliente | 2 min/cliente | 85% |
| Generación balanza de comprobación XML | Mensual | 20 min/cliente | 3 min/cliente | 85% |
| Generación pólizas XML | Mensual | 30 min/cliente | 5 min/cliente | 83% |
| Validación estructura contra XSD | Mensual | 10 min/cliente | Automático | 100% |
| Envío al portal SAT | Mensual | 15 min/cliente | 2 min/cliente | 85% |

### 1.3 Dolor Principal que Resuelve

**Problema central:** Los contadores dedican 1.5-2 horas por cliente mensualmente a generar y enviar contabilidad electrónica. Errores en códigos agrupadores (100-800) o estructura XML causan rechazo del SAT y multas de $15,000-$30,000 MXN por envío extemporáneo o información incorrecta.

### 2.4 Estructura de Balanza de Comprobación

**Campos Obligatorios (Anexo 24 Sección B):**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<Balanza xmlns:xsd="http://www.w3.org/2001/XMLSchema"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xmlns="http://www.sat.gob.mx/esquemas/Cont/eBalanza"
         xsi:schemaLocation="http://www.sat.gob.mx/esquemas/Cont/eBalanza http://www.sat.gob.mx/esquemas/Cont/eBalanza/eBalanza.xsd"
         version="1.3"
         RFC="XAXX010101000"
         Mes="03"
         Año="2026"
         TipoEnvio="N">
  <Cuenta NumeroCuenta="102.01"
          SaldoInicial="100000.00"
          Debe="500000.00"
          Haber="450000.00"
          SaldoFinal="150000.00"/>
</Balanza>
```

**Atributos del elemento Balanza:**

| Atributo | Tipo | Obligatorio | Descripción |
|----------|------|-------------|-------------|
| version | String | Sí | Versión del estándar (actual: "1.3") |
| RFC | String | Sí | RFC del contribuyente (12-13 caracteres) |
| Mes | String | Sí | Mes del reporte (01-13, 13=anual) |
| Año | String | Sí | Año del reporte (ej: "2026") |
| TipoEnvio | String | Sí | `N` = Normal, `C` = Complementaria |
| FechaModBalanza | Date | Solo si es C | Fecha de modificación (YYYY-MM-DD) |

**Atributos del elemento Cuenta:**

| Atributo | Tipo | Obligatorio | Descripción |
|----------|------|-------------|-------------|
| NumeroCuenta | String | Sí | Número de cuenta del catálogo |
| SaldoInicial | Decimal | Sí | Saldo al inicio del periodo |
| Debe | Decimal | Sí | Suma de movimientos deudores |
| Haber | Decimal | Sí | Suma de movimientos acreedores |
| SaldoFinal | Decimal | Sí | Saldo al final del periodo |

**Tipos de Envío:**
- `N` = Normal (primera vez que se envía el mes)
- `C` = Complementaria (corrección de balanza previamente enviada)

### 3.2 Algoritmo: Generación de Catálogo de Cuentas XML

```python
"""
Generador de Catálogo de Cuentas XML - Anexo 24 RMF 2026
Versión: 1.0
Autor: Equipo de Desarrollo IDP-App
"""

import xml.etree.ElementTree as ET
from xml.dom import minidom
from typing import Dict, List, Optional
from datetime import datetime


class GeneradorCatalogoCuentas:
    """
    Genera archivos XML de catálogo de cuentas según Anexo 24 RMF 2026.
    
    El catálogo de cuentas es el documento en el que se detallan de forma
    ordenada todos los números (claves) y nombres de las cuentas de activo,
    pasivo, capital, ingresos, costos, gastos y cuentas de orden.
    
    Attributes:
        rfc: RFC del contribuyente (12-13 caracteres)
        version: Versión del estándar (default: "1.3")
        namespace: Namespace oficial del SAT
    """
    
    # Namespace oficial del SAT para catálogo de cuentas
    NAMESPACE = "http://www.sat.gob.mx/esquemas/Cont/eCatalogoCuentas"
    SCHEMA_LOCATION = "http://www.sat.gob.mx/esquemas/Cont/eCatalogoCuentas http://www.sat.gob.mx/esquemas/Cont/eCatalogoCuentas/eCatalogoCuentas.xsd"
    
    def __init__(self, rfc: str, version: str = "1.3"):
        """
        Inicializa el generador de catálogo de cuentas.
        
        Args:
            rfc: RFC del contribuyente (12-13 caracteres)
            version: Versión del estándar Anexo 24 (default: "1.3")
            
        Raises:
            ValueError: Si el RFC no tiene 12-13 caracteres
        """
        if not self._validar_rfc(rfc):
            raise ValueError(f"RFC inválido: {rfc}. Debe tener 12-13 caracteres.")
        
        self.rfc = rfc.upper()
        self.version = version
        
    def _validar_rfc(self, rfc: str) -> bool:
        """
        Valida que el RFC tenga 12-13 caracteres.
        
        Args:
            rfc: RFC a validar
            
        Returns:
            True si es válido, False en caso contrario
        """
        return 12 <= len(rfc) <= 13
    
    def generar_xml(self, cuentas: List[Dict]) -> str:
        """
        Genera el XML del catálogo de cuentas.
        
        Args:
            cuentas: Lista de diccionarios con estructura:
                [
                    {
                        'numero': '102.01',
                        'descripcion': 'Bancos BBVA',
                        'nivel': 2,
                        'naturaleza': 'D',  # D=Deudora, A=Acreedora
                        'codigo_agrupador': '102.01'
                    }
                ]
        
        Returns:
            String con el contenido XML formateado
            
        Ejemplo:
            >>> gen = GeneradorCatalogoCuentas("XAXX010101000")
            >>> cuentas = [
            ...     {'numero': '102.01', 'descripcion': 'Bancos BBVA', 
            ...      'nivel': 2, 'naturaleza': 'D', 'codigo_agrupador': '102.01'}
            ... ]
            >>> xml = gen.generar_xml(cuentas)
            >>> print(xml[:100])
            '<?xml version='1.0' encoding='UTF-8'?>\\n<Catalogo ...'
        """
        # Elemento raíz
        catalogo = ET.Element('Catalogo')
        catalogo.set('version', self.version)
        catalogo.set('RFC', self.rfc)
        
        # Agregar namespaces
        catalogo.set('xmlns:xsd', 'http://www.w3.org/2001/XMLSchema')
        catalogo.set('xmlns:xsi', 'http://www.w3.org/2001/XMLSchema-instance')
        catalogo.set('xmlns', self.NAMESPACE)
        catalogo.set('xsi:schemaLocation', f"{self.NAMESPACE} {self.SCHEMA_LOCATION}")
        
        # Agregar cuentas
        for cuenta in cuentas:
            c = ET.SubElement(catalogo, 'Cuenta')
            c.set('NumeroCuenta', cuenta['numero'])
            c.set('CodigoAgrupador', cuenta['codigo_agrupador'])
            c.set('Concepto', cuenta['descripcion'])
            c.set('Nivel', str(cuenta['nivel']))
            c.set('Naturaleza', cuenta['naturaleza'])
        
        # Convertir a string con formato
        xml_str = ET.tostring(catalogo, encoding='utf-8')
        xml_pretty = minidom.parseString(xml_str).toprettyxml(indent="  ", encoding='utf-8')
        
        return xml_pretty.decode('utf-8')
    
    def guardar_archivo(self, cuentas: List[Dict], ruta_salida: str = None) -> str:
        """
        Genera y guarda el archivo XML.
        
        Args:
            cuentas: Lista de cuentas (ver generar_xml)
            ruta_salida: Ruta opcional para guardar el archivo
            
        Returns:
            Ruta completa del archivo generado
            
        Ejemplo:
            >>> gen = GeneradorCatalogoCuentas("XAXX010101000")
            >>> ruta = gen.guardar_archivo(cuentas, "./output/")
            >>> print(ruta)
            './output/XAXX010101000202603CT.xml'
        """
        xml_content = self.generar_xml(cuentas)
        
        # Nombre del archivo: RFC + Año + Mes + CT + .xml
        anio = datetime.now().year
        mes = datetime.now().month
        nombre_archivo = f"{self.rfc}{anio}{str(mes).zfill(2)}CT.xml"
        
        if ruta_salida:
            ruta_completa = f"{ruta_salida.rstrip('/')}/{nombre_archivo}"
        else:
            ruta_completa = nombre_archivo
        
        with open(ruta_completa, 'w', encoding='utf-8') as f:
            f.write(xml_content)
        
        return ruta_completa
```

```python
                 tipo_envio: str = "N", version: str = "1.3"):
        """
        Inicializa el generador de balanza de comprobación.
        
        Args:
            rfc: RFC del contribuyente (12-13 caracteres)
            mes: Mes del reporte (1-13, 13=anual)
            anio: Año del reporte
            tipo_envio: 'N' (Normal) o 'C' (Complementaria)
            version: Versión del estándar
            
        Raises:
            ValueError: Si mes no está entre 1-13 o tipo_envio no es N/C
        """
        if not 1 <= mes <= 13:
            raise ValueError(f"Mes inválido: {mes}. Debe estar entre 1-13.")
        
        if tipo_envio not in ['N', 'C']:
            raise ValueError(f"TipoEnvio inválido: {tipo_envio}. Debe ser 'N' o 'C'.")
        
        self.rfc = rfc.upper()
        self.mes = mes
        self.anio = anio
        self.tipo_envio = tipo_envio
        self.version = version
        self.fecha_modificacion = None
    
    def set_fecha_modificacion(self, fecha: str):
        """
        Establece la fecha de modificación para balanza complementaria.
        
        Args:
            fecha: Fecha en formato YYYY-MM-DD
        """
        if self.tipo_envio == 'C':
            self.fecha_modificacion = fecha
    
    def generar_xml(self, cuentas: List[Dict]) -> str:
        """
        Genera el XML de la balanza de comprobación.
        
        Args:
            cuentas: Lista de diccionarios con estructura:
                [
                    {
                        'numero': '102.01',
                        'saldo_inicial': 100000.00,
                        'debe': 500000.00,
                        'haber': 450000.00,
                        'saldo_final': 150000.00
                    }
                ]
        
        Returns:
            String con el contenido XML formateado
            
        Ejemplo:
            >>> gen = GeneradorBalanzaComprobacion("XAXX010101000", 3, 2026, "N")
            >>> cuentas = [
            ...     {'numero': '102.01', 'saldo_inicial': 100000.00,
            ...      'debe': 500000.00, 'haber': 450000.00, 'saldo_final': 150000.00}
            ... ]
            >>> xml = gen.generar_xml(cuentas)
        """
        # Elemento raíz
        balanza = ET.Element('Balanza')
        balanza.set('version', self.version)
        balanza.set('RFC', self.rfc)
        balanza.set('Mes', str(self.mes).zfill(2))
        balanza.set('Anio', str(self.anio))
        balanza.set('TipoEnvio', self.tipo_envio)
        
        # Agregar fecha de modificación si es complementaria
        if self.tipo_envio == 'C' and self.fecha_modificacion:
            balanza.set('FechaModBalanza', self.fecha_modificacion)
        
        # Agregar namespaces
        balanza.set('xmlns:xsd', 'http://www.w3.org/2001/XMLSchema')
        balanza.set('xmlns:xsi', 'http://www.w3.org/2001/XMLSchema-instance')
        balanza.set('xmlns', self.NAMESPACE)
        balanza.set('xsi:schemaLocation', f"{self.NAMESPACE} {self.SCHEMA_LOCATION}")
        
        # Agregar cuentas
        for cuenta in cuentas:
            c = ET.SubElement(balanza, 'Cuenta')
            c.set('NumeroCuenta', cuenta['numero'])
            c.set('SaldoInicial', f"{cuenta['saldo_inicial']:.2f}")
            c.set('Debe', f"{cuenta['debe']:.2f}")
            c.set('Haber', f"{cuenta['haber']:.2f}")
            c.set('SaldoFinal', f"{cuenta['saldo_final']:.2f}")
        
        # Convertir a string con formato
        xml_str = ET.tostring(balanza, encoding='utf-8')
        xml_pretty = minidom.parseString(xml_str).toprettyxml(indent="  ", encoding='utf-8')
        
        return xml_pretty.decode('utf-8')
    
    def validar_cuadre(self, cuentas: List[Dict]) -> Dict:
        """
        Valida que la balanza esté cuadrada (suma debe = suma haber).
        
        Args:
            cuentas: Lista de cuentas con movimientos
            
        Returns:
            Diccionario con resultado de validación:
            {
                'cuadrada': bool,
                'total_debe': float,
                'total_haber': float,
                'diferencia': float
            }
        """
        total_debe = sum(c['debe'] for c in cuentas)
        total_haber = sum(c['haber'] for c in cuentas)
        diferencia = abs(total_debe - total_haber)
        
        return {
            'cuadrada': diferencia < 0.01,  # Tolerancia de 1 centavo
            'total_debe': total_debe,
            'total_haber': total_haber,
            'diferencia': diferencia
        }
```

```python
"""
Validador de XML de Contabilidad Electrónica contra Schema XSD del SAT
Versión: 1.0
Autor: Equipo de Desarrollo IDP-App
"""

from lxml import etree
from typing import Dict, List
import os


class ValidadorXMLContabilidad:
    """
    Valida archivos XML de contabilidad electrónica contra los schemas XSD
    oficiales del SAT.
    
    Attributes:
        ruta_xsd: Ruta al directorio con los schemas XSD del SAT
    """
    
    # URLs oficiales de schemas XSD del SAT
    XSD_BALANZA = "http://www.sat.gob.mx/esquemas/Cont/eBalanza/eBalanza.xsd"
    XSD_POLIZAS = "http://www.sat.gob.mx/esquemas/Cont/ePolizas/ePolizas.xsd"
    XSD_CATALOGO = "http://www.sat.gob.mx/esquemas/Cont/eCatalogoCuentas/eCatalogoCuentas.xsd"
    
    def __init__(self, ruta_xsd: str = None):
        """
        Inicializa el validador.
        
        Args:
            ruta_xsd: Ruta al directorio con archivos XSD locales.
                     Si es None, intenta descargar de URLs del SAT.
        """
        self.ruta_xsd = ruta_xsd
    
    def validar_xml(self, xml_path: str, xsd_path: str) -> Dict:
        """
        Valida un archivo XML contra un schema XSD.
        
        Args:
            xml_path: Ruta al archivo XML a validar
            xsd_path: Ruta al archivo XSD del SAT
            
        Returns:
            Diccionario con resultado de validación:
            {
                'valido': bool,
                'errores': List[str],
                'archivo': str
            }
            
        Ejemplo:
            >>> validador = ValidadorXMLContabilidad()
            >>> resultado = validador.validar_xml(
            ...     "XAXX010101000202603BN.xml",
            ...     "schemas/eBalanza.xsd"
            ... )
            >>> print(f"Válido: {resultado['valido']}")
        """
        try:
            # Cargar schema
            with open(xsd_path, 'rb') as f:
                schema_doc = etree.parse(f)
                schema = etree.XMLSchema(schema_doc)
            
            # Cargar XML
            xml_doc = etree.parse(xml_path)
            
            # Validar
            schema.assertValid(xml_doc)
            
            return {
                'valido': True,
                'errores': [],
                'archivo': xml_path
            }
            
        except etree.XMLSchemaError as e:
            return {
                'valido': False,
                'errores': [str(e)],
                'archivo': xml_path
            }
        except FileNotFoundError as e:
            return {
                'valido': False,
                'errores': [f"Archivo no encontrado: {str(e)}"],
                'archivo': xml_path
            }
        except Exception as e:
            return {
                'valido': False,
                'errores': [f"Error inesperado: {str(e)}"],
                'archivo': xml_path
            }
    
    def validar_balanza(self, xml_path: str) -> Dict:
        """
        Valida una balanza de comprobación XML.
        
        Args:
            xml_path: Ruta al archivo XML de balanza
            
        Returns:
            Resultado de validación
        """
        xsd_path = os.path.join(self.ruta_xsd or '.', 'eBalanza.xsd')
        return self.validar_xml(xml_path, xsd_path)
    
    def validar_polizas(self, xml_path: str) -> Dict:
        """
        Valida pólizas del periodo XML.
        
        Args:
            xml_path: Ruta al archivo XML de pólizas
            
        Returns:
            Resultado de validación
        """
        xsd_path = os.path.join(self.ruta_xsd or '.', 'ePolizas.xsd')
        return self.validar_xml(xml_path, xsd_path)
    
    def validar_catalogo(self, xml_path: str) -> Dict:
        """
        Valida catálogo de cuentas XML.
        
        Args:
            xml_path: Ruta al archivo XML de catálogo
            
        Returns:
            Resultado de validación
        """
        xsd_path = os.path.join(self.ruta_xsd or '.', 'eCatalogoCuentas.xsd')
        return self.validar_xml(xml_path, xsd_path)


# Ejemplo de uso
if __name__ == "__main__":
    validador = ValidadorXMLContabilidad(ruta_xsd="./schemas")
    
    # Validar balanza
    resultado = validador.validar_balanza("XAXX010101000202603BN.xml")

        print("✓ XML válido contra schema XSD del SAT")
    else:
        print("✗ XML inválido:")
        for error in resultado['errores']:
            print(f"  - {error}")
```

## 5. Limitantes y Restricciones

### 5.1 Limitación 1: Envío Solo Vía Buzón Tributario

**Problema:**
El SAT no proporciona API pública para envío automatizado de contabilidad electrónica. Todos los envíos deben realizarse manualmente a través del portal del SAT (Buzón Tributario).

**Solución:**
1. **Generación automatizada de XML:** Crear archivos listos para carga manual
2. **Automatización Selenium/Playwright:** Script de carga automatizada (bajo riesgo, requiere mantenimiento)
3. **Servicios de terceros:** APIs de proveedores autorizados (costo adicional)

**Impacto:**
- Tiempo de envío manual: 2-5 min por archivo
- Para 50 clientes: 1.5-4 horas mensuales
- Riesgo de error humano en carga

### 5.2 Limitación 2: Cambios en Anexo 24

**Problema:**
El SAT puede modificar el Anexo 24 anualmente (diciembre-enero), requiriendo actualizaciones en generadores XML.

**Solución:**
1. **Monitoreo DOF:** Revisar Diario Oficial en diciembre-enero
2. **Arquitectura flexible:** Separar lógica de generación de estructura XML
3. **Versionado:** Soportar múltiples versiones (1.2, 1.3, etc.)

**Impacto:**
- Tiempo de actualización: 4-8 horas por cambio mayor
- Riesgo de obsolescencia si no se monitorea

### 5.3 Riesgos Técnicos Identificados

| Riesgo | Probabilidad | Impacto | Mitigación | Owner |
|--------|--------------|---------|------------|-------|
| Error en códigos agrupadores | MEDIA | ALTO | Validación previa contra catálogo SAT | Backend |
| Rechazo por estructura XML inválida | BAJA | ALTO | Validación con schema XSD oficial | QA |
| Cambios en Anexo 24 (diciembre) | BAJA | ALTO | Monitoreo DOF, arquitectura versionada | Tech Lead |
| Timeout en generación XML (>10s) | BAJA | MEDIO | Optimización, procesamiento por lotes | Backend |
| Error en cuadre de balanza | MEDIA | ALTO | Validación automática Debe=Haber | Backend |
